## Definition of Done

A task can be considered done when it passes the following checklist:

- [ ] Code has been reviewed and approved.
- [ ] No critical or high-priority bugs remain.
- [ ] All tests have passed (functional, integration, performance).
- [ ] Functional acceptance criteria have been met.
- [ ] Documentation has been updated.
- [ ] Final deployment to production or staging environment has been completed.


## Product Backlog

The product backlog contains all outstanding work for the project. Each item is estimated using the Fibonacci sequence for complexity, and tasks are managed on a Scrum board with the following columns: **To Do → In Progress → Review → Done**.

### Backlog Guidelines
- Complexity is estimated using the Fibonacci sequence.
- Sprint timeframe: 1–3 weeks per sprint.
- Progress is tracked via a burndown chart.
- Discussions (approvals, corrections, what worked/didn't work, bugs and fixes, etc.) are documented after each sprint.

### Initial Backlog Items

1. Define project requirements and scope
2. Set up Git repository (branching strategy, roles, project structure, commit rules)
3. Set up project board (Atlassian)
4. Choose tech stack and document it
5. Create initial Product Backlog
6. Define "Definition of Done"
7. Plan Sprint 1 (pick tasks, assign owners)


## Story Points (Complexity Assessment)

Complexity is assessed using the **Fibonacci scale** (the higher the number, the greater the complexity).

| Points | Meaning |
|--------|---------|
| 1 | Trivial: 30 minutes or less |
| 2 | Easy: a couple of hours |
| 3 | Medium: up to a full day |
| 5 | Hard: multiple days |
| 8 | Very hard: should be broken down into smaller tasks |
